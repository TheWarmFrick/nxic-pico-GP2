# NXIC-pico

USBキーボード・マウスの入力を Nintendo Switch (初代) の Pro コントローラー入力に変換するファームウェアです。
[NXIC](https://github.com/mizuyoukanao/NXIC) (Raspberry Pi 版) のキー配置を踏襲した、Waveshare **RP2350-USB-A** 向けの pico-sdk 実装です。

```
[Switch ドック] --USB-C--> [RP2350-USB-A] <--USB-A-- [USBハブ] <-- キーボード / マウス
                (プロコンとして認識)       (PIO-USB ホスト)
```

- ネイティブUSB (USB-C側): TinyUSB デバイススタックで Pro コントローラー (VID 057E / PID 2009) をエミュレート
- USB-Aポート (GP12=D+ / GP13=D-): [Pico-PIO-USB](https://github.com/sekigon-gonnoc/Pico-PIO-USB) + TinyUSB ホストスタック。ハブ経由で複数のキーボード・マウスを同時接続可能
- プロコンプロトコル ([dekuNukem/Nintendo_Switch_Reverse_Engineering](https://github.com/dekuNukem/Nintendo_Switch_Reverse_Engineering) 参照) のハンドシェイク・サブコマンド応答・SPIフラッシュ(キャリブレーション)読み出しを実装

## 必要なハードウェア準備

**RP2350-USB-A の USB-A ポートをホストとして使うには R13 (基板の6番ピン近くにある D+ の 1.5kΩ プルアップ抵抗) を取り外すか、電源投入前にあらかじめUSB-A ポートに対象デバイスを接続しておく必要があります。**
上記を満たさないとキーボード・マウスが正しく認識されません。

- 電源は Switch ドックの USB から供給されます。消費電力の大きいデバイスを繋ぐ場合はセルフパワーのハブを使ってください。
- Switch 本体の「設定 → コントローラーとセンサー → Proコントローラーの有線通信」を ON にしてください。

## ビルド

pico-sdk 2.x (2.1 以降推奨) が必要です。Pico-PIO-USB は `lib/Pico-PIO-USB` に置くか、無ければ CMake が自動でダウンロードします。

```sh
# 任意: 手動で取得する場合
git clone https://github.com/sekigon-gonnoc/Pico-PIO-USB lib/Pico-PIO-USB

mkdir build && cd build
cmake .. -G Ninja -DPICO_SDK_PATH=<pico-sdkのパス>
ninja
```

VS Code の Raspberry Pi Pico 拡張でもそのまま開けます (ボードは `pico2` / RP2350)。

書き込みは BOOTSEL ボタンを押しながら USB-C を PC に接続し、`build/nxic_pico.uf2` をドラッグ&ドロップしてください。

## ジャイロ変換ロジック (NXIC からの変更点)

NXIC はマウスレポートの移動量をそのままジャイロ値に「上書き」していたため、マウスのポーリングが速い場合に移動量を取りこぼし、感度も経験的な定数 (`mouse_threshold`) 頼みでした。本実装では以下のように見直しています。

1. **蓄積方式**: マウスの移動量はレポート間で積算され、一切失われません (1000Hz マウスでも取りこぼしなし)。
2. **角度保存**: 「マウス何カウントで何度回転するか」を基準に変換します。Switch は 1 レポートあたり 3 フレーム × 5ms のジャイロを積分するので、`角速度 = 角度 ÷ 15ms` として正確に符号化します。
3. **飽和時の繰り越し**: int16 のジャイロレンジ (約 33.6°/レポート) を超える高速フリックは、残りの角度を次のレポートに繰り越して最終的な向きを保証します。
4. **仮想姿勢の追跡と加速度計への反映**: 実際に送信したジャイロ値を積分して仮想的なコントローラー姿勢 (ピッチ角) を保持し、加速度計にはその姿勢での重力ベクトル `(sinθ, 0, cosθ)×1G` を毎フレーム報告します。ジャイロと加速度計が常に同じ剛体運動を記述するため、センサーフュージョンを行うゲームでも姿勢が引き戻されたりしません。プロコンのボディ座標系は X=前方 / Y=横方向 / Z=上で、ピッチは **Y軸まわり**の回転です。
5. **ヨー軸の物理的整合**: ヨーは「ワールド鉛直軸まわりの回転」としてモデル化し、ピッチしている間は角速度をボディX/Z軸に `(ψ̇·sinθ, 0, ψ̇·cosθ)` と正しく分配します。上を向いた状態でマウスを横に振っても、意図通り水平旋回になります。
6. **縦横の独立した感度**: Splatoon 系のゲームは横視点をジャイロの積分 (相対)、**縦視点をコントローラーの絶対的な傾き**に紐付けています。そのため縦は「±`PITCH_LIMIT_DEG` の範囲で傾きを位置決めする」操作になり、横 (`GYRO_COUNTS_PER_360`) とは別の感度 `PITCH_COUNTS_PER_360` で調整します。限界を超えた入力は捨てるので、マウスを戻せば即座に反応します。ゲーム側のカメラリセットと仮想姿勢がズレた場合は **M キー**で水平にリセットできます (ゲーム内カメラリセットと同時に押すのが確実です)。

感度・反転などは [src/config.h](src/config.h) で調整します:

```c
#define GYRO_COUNTS_PER_360  8000.0f  // 横: 360°旋回に必要なマウスカウント数 (小さいほど高感度)
#define PITCH_COUNTS_PER_360 8000.0f  // 縦: 傾き変化の感度 (小さいほど高感度)
#define GYRO_INVERT_YAW      0        // 左右反転
#define GYRO_INVERT_PITCH    0        // 上下反転
#define PITCH_LIMIT_DEG      80.0f    // 仮想ピッチの可動範囲 (±deg, 90未満)
#define KEY_PITCH_RESET      HID_KEY_M // 仮想ピッチのリセットキー
#define IMU_AXIS_SIGN_X      1        // 実機と軸の向きが合わない場合の符号修正 (+1/-1)
#define IMU_AXIS_SIGN_Y      1        //   (該当軸のジャイロと加速度が同時に反転します)
#define IMU_AXIS_SIGN_Z      1
```

`GYRO_COUNTS_PER_360` はマウスの DPI に依存します。800 DPI なら 8000 カウント ≒ 25.4cm の移動で 360° です。ゲーム内のジャイロ感度設定と合わせて調整してください。エイムの上下/左右が逆になる場合は `GYRO_INVERT_*` を調整してください。上下の視点が端まで届かない場合は `PITCH_LIMIT_DEG` を増やすか、ゲーム内のジャイロ感度を上げてください。

### IMU デバッグキー (動作確認用)

書き込み直さずにゲーム内で加速度計の扱いを A/B テストできるキーを用意しています (挙動が確定したら削除予定):

| キー | 動作 |
|---|---|
| Ctrl+Alt+1 | 加速度計の符号を反転 (静止時 +4096 ⇔ -4096) |
| Ctrl+Alt+2 | 加速度計のモードを切替: 姿勢追従 → 水平固定 → ゼロ (NXIC互換) → … |

既定は「姿勢追従・静止時 +4096」です (SDL のプロコンドライバと実機テストで確認済みの符号)。ゼロ (NXIC互換) にするとゲームは加速度補正を行えなくなり、上下も純ジャイロの相対操作になります。

## 制限事項

- マウスは HID レポートディスクリプタを解析して X/Y/ボタンの位置を自動検出します (8/12/16bit 移動量・レポートID付きに対応)。解析に失敗した場合はブートプロトコルにフォールバックします。
- キーボードは **ブートプロトコル** で動かします (長さ・値域を検証し、不正なレポートは破棄)。ブートプロトコル非対応のキーボードは認識されません。
- 振動 (ランブル) と NFC/amiibo は未対応です (プロトコル上は ACK を返すのでエラーにはなりません)。
- Switch との接続は USB (ドック) のみです。Bluetooth接続には対応していません。

## Web 設定 (ブラウザからの設定変更)

GP2040-CE の Web コンフィグと同様に、USB NCM ネットワークデバイスとして列挙するモードを備えています。

1. 動作中 (コントローラーモード) にキーボードで **Ctrl+Alt+W** を押すと再起動して設定モードに入ります (LED が紫になります)
2. 本体の USB-C を PC に接続すると「NXIC Web Config」というネットワークアダプタとして認識されます (Windows 10/11・macOS・Linux で追加ドライバ不要)
3. **そのアダプタの IPv4 を手動設定にします**: IP アドレス `192.168.7.2`、サブネットマスク `255.255.255.0` (プレフィックス長 24)、ゲートウェイ・DNS は空欄
   - Windows: 設定 → ネットワークとインターネット → イーサネット → 該当アダプタ → 「IP 割り当て」を手動 (IPv4)
   - ※ DHCP サーバも内蔵していますが、環境によって機能しないことが確認されているため手動設定を推奨します
4. ブラウザで **http://192.168.7.1** を開くと設定ページが表示されます
5. 設定できる項目: ジャイロ感度 (ヨー/ピッチ独立)・上下左右反転・ピッチ可動域・連射速度・LED輝度・全キー配置 (クリックしてキーを押すだけで変更)
6. 「保存」でフラッシュに書き込み、「コントローラーモードで再起動」で通常動作に戻ります (電源を挿し直しても通常モードで起動します)

設定はフラッシュの最終セクタに保存され、ファームウェアを書き込み直しても保持されます。`config.h` の値は初期値 (未保存時のデフォルト) として使われます。

### 設定モードの LED 診断

設定モード中の LED はどこまで通信が進んだかを示します:

| 色 | 状態 |
|---|---|
| 紫 | 起動直後 (ホストからのフレーム未受信) |
| 青 | ホストからイーサネットフレーム受信 (USBデータパス正常) |
| シアン | DHCP でアドレスを払い出した |
| 緑 | HTTP リクエストを処理した (ページ表示OK) |

### つながらないときは

- Windows で「識別されていないネットワーク」表示になるのは正常です (ゲートウェイの無いリンクのため)。
- LED が青のままなのは DHCP が完了していない状態ですが、上記の手動 IP 設定をしていれば問題ありません (アクセスできれば緑になります)。
- システムプロキシを使っている環境では 192.168.7.1 がプロキシ経由になって開けないことがあります。プロキシ例外に追加するか、`curl http://192.168.7.1/api/config` で確認してください。

## LED (GP16 の WS2812 RGB)

- 青点滅: Switch とのハンドシェイク待ち
- 緑点灯: 動作中・姿勢追従モード (既定)
- 黄点灯: 動作中・加速度水平固定モード (デバッグ)
- 赤点灯: 動作中・加速度ゼロモード (デバッグ, NXIC互換)
- 紫点灯: Web 設定モード
